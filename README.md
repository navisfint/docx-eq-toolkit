# docx 公式段落 → 无框线两列表

把 Word 里「公式 + 编号」混排的段落，重排成**无框线两列表格**：左列公式、右列编号（右对齐）。
公式用 MathType / OLE 插入时，普通做法会破坏对象——这个脚本**只动容器，不动内容**。

## 解决什么问题

论文里的公式段落常常是 `（1）` 编号直接跟在公式后面，靠空格和 Tab 硬凑对齐。
字号一变、缩进一调，整列就歪了。放进两列表格能永久对齐，但手动拖拽会带来两个后果：

- MathType 公式变成图片，双击不能编辑
- Word 的公式（OMML）被转成纯文本，丢失结构

这个脚本绕开这两点：**OLE 对象、关系 id（`rId*`）、嵌入流全部原样搬移**，
`document.xml` 里只改变容器的嵌套层级和段落属性。

## 核心做法

```
原结构                              新结构
─────────────────────────────      ─────────────────────────────
w:p  ── r ── （1）                 w:tbl
     └─ r ── oMath / object             └─ w:tr
                                            ├─ w:tc ── 公式段落（原 pPr 保留）
                                            └─ w:tc ── 编号段落
```

### 让公式真正居中

右列宽度定死为 900 twips（约 45pt，刚好放下 `（n）` 再加 15pt 余量），
然后**把左列段落的左缩进设成和右列一样宽**：

```python
TEXT_W  = 10342   # 版心宽 (11906 - 782 - 782) twips
RIGHT_W = 900     # 右列宽
IND_LEFT = RIGHT_W
```

这样左列可用区的中心恰好落在版心中心，视觉上公式是真的居中，而不是「在左格里居中」。
不加这一步，带编号的公式会整体偏左，一眼能看出来。

## 用法

```bash
python docx_eq_to_table.py 论文.docx
# 输出 论文_公式表格.docx
```

识别规则：段落纯文本匹配 `^（[1-7]）$` 才处理，其余段落原样保留。
编号范围可在 `NUM_RE` 里改。

## 文件

| 文件 | 说明 |
|---|---|
| `docx_eq_to_table.py` | 主脚本，160 行，仅用标准库 `zipfile` + `re` |
| `omml2mml_wrap.xsl` | 配套 XSL：把 OMML 公式转 MML 字符流，用于排查转换后的公式是否正确 |

## 限制

- 只处理 `（1）`~`（7）` 这种全角括号编号，其他编号格式需改 `NUM_RE`
- 假定编号段落紧跟公式段落，跨段落引用不支持
- 不做备份，跑之前自己留一份原件
